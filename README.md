# 网页定制 · Chrome 扩展

为指定网站注入你自己的 CSS 和 JavaScript，让网页按你喜欢的样子运行。适用于 Chrome 120+，也可用于 Edge 等 Chromium 内核浏览器。

## 安装

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 打开右上角的 **开发者模式**。
3. 点击 **加载已解压的扩展程序**，选择 `site-tweaker` 文件夹。
4. 推荐：点开本扩展的 **详情**，打开 **允许用户脚本**（Allow User Scripts）开关。
   - 打开后，JS 由浏览器的用户脚本接口注入，不会被网站的安全策略（CSP）拦截。
   - 不打开也能用：CSS 不受影响，JS 以兼容模式运行，但在 GitHub 这类 CSP 严格的网站上会被拦截。
   - Chrome 120–137 没有这个开关，开启上面第 2 步的开发者模式即可。
5. 如果扩展详情页出现「Chrome 建议您检查此扩展程序」，点 **保留**。这是浏览器对所有非商店扩展的例行提示。
6. 开发者模式要一直开着：关掉后，Chrome 会在下次重新加载时停用已解压的扩展。

安装后会自动打开规则管理页，并附带一条作用于 example.com 的示例规则，打开 https://example.com 就能看到效果。

## 使用

- **工具栏弹窗**：显示当前网站有哪些规则在生效，可以逐条开关、一键为当前网站新建规则，以及总开关。图标上的数字是当前页面生效的规则数。
- **规则管理页**：新建、编辑、复制、删除、导入/导出规则。`Ctrl + S` 保存。
- **CSS**：保存后，已打开的页面立刻更新，不用刷新。样式会排在网页自身样式之后；如果还是被覆盖，加上 `!important`。
- **JS**：保存后刷新页面生效，每次页面加载运行一次。代码被包在 async 函数里，可以直接写 `await`；出错时控制台会提示是哪条规则。
  - 运行时机：页面开始加载时 / DOM 就绪时 / 页面加载完成后（默认）。
  - 运行环境：**页面环境**能访问网页自己的全局变量，和在开发者工具控制台里运行的效果一样；**隔离环境**与网页脚本互不干扰。兼容模式下一律在页面环境运行。

### 快捷消除（默认快捷键 `Alt+Shift+X`）

在弹窗里点「快捷消除」，然后：

- 鼠标指到哪里，就高亮哪个元素，标签上显示元素名称和尺寸。
- `Tab` 切换到外一层元素，`Shift+Tab` 回到内一层。
- 单击（或按 `Enter`）隐藏当前高亮的元素。可以连续隐藏多个，`Ctrl+Z` 或工具条上的「撤销」撤回上一个。
- `Esc` 或「完成」退出。工具条可以拖动位置。

隐藏的元素会以 `选择器 { display: none !important; }` 的形式，写进本网站专用的「快捷消除 · 域名」规则，刷新后依然有效。要恢复某个元素，在管理页或代码小窗里删掉对应的那一行，或者停用整条规则。

- 用 `display: none` 而不是 `visibility: hidden`，是为了让元素连同它占的位置一起消失。
- 选择器优先使用稳定的 ID 和类名，会自动跳过构建工具生成的随机类名，只在必要时才用序号，尽量保证刷新后还能选中同一个元素。
- 快捷消除只作用于页面本身。广告这类嵌在 iframe 里的内容，可以直接选中整个 iframe 隐藏。

### 代码小窗（默认快捷键 `Alt+Shift+C`）

在弹窗里点「代码小窗」，页面右下角会浮出一个小窗，列出作用于当前页面的所有规则（包括已停用的）以及它们的 CSS 和 JS：

- 每条规则都可以就地开关，CSS 的变化立即生效。
- 「复制」复制代码，「编辑」在管理页打开这条规则。
- 小窗可以拖动标题栏移动，拖右下角调整大小；按 `Esc`、点 ✕，或再按一次快捷键关闭。

快捷键可以在 `chrome://extensions/shortcuts`（Edge 为 `edge://extensions/shortcuts`）里修改。如果和其他扩展冲突，浏览器不会自动分配，需要在那里手动设置。

### 「适用网站」的写法

每行一条：

| 写法 | 含义 |
| --- | --- |
| `github.com` | 该域名及其所有子域名，任意页面 |
| `www.zhihu.com/question` | 该域名下，路径以 `/question` 开头的页面 |
| `localhost:3000` | 本机指定端口（会拆成 http 和 https 两条，因为 Chrome 不允许 `*://` 带端口） |
| `https://*.example.com/news/*` | Chrome 标准匹配模式，按原样精确匹配 |
| `!gist.github.com` | 排除这些网址 |
| `*` | 所有网站 |
| `# 备注` | 注释，会被忽略 |

管理页会实时显示每行转换成的匹配模式；「写法说明与网址测试」里可以粘贴网址，检查规则会不会生效。

## 文件结构

```
site-tweaker/
  manifest.json        扩展清单（Manifest V3）
  background.js        后台：注册用户脚本、兼容模式运行 JS、角标、快捷键
  content.js           内容脚本：插入并实时更新 CSS，请求运行 JS
  lib/rules.js         网址匹配、规则规范化（各处共用）
  lib/tools.js         把页面内工具注入到标签页（弹窗和后台共用）
  inpage/              页面内工具：快捷消除（picker.js）、代码小窗（viewer.js）、共用浮层（ui.js）
  options/             规则管理页
  popup/               工具栏弹窗
  ui/                  共用样式和代码编辑框
  icons/               图标
tools/
  test-rules.js        匹配逻辑单元测试：node --test tools/test-rules.js
  e2e-test.js          真实浏览器端到端测试（见下）
  make-icons.js        重新生成图标：node tools/make-icons.js
  preview-server.js    用模拟的 chrome API 在普通浏览器里预览界面
```

### 端到端测试

需要 [Chrome for Testing](https://googlechromelabs.github.io/chrome-for-testing/)，因为品牌版 Chrome 不允许用命令行加载扩展。测试会启动无界面浏览器，加载扩展，用一个本地测试网站检查以下内容：兼容模式与用户脚本模式、严格 CSP 和 Trusted Types、实时更新、单页应用切换网址、管理页、弹窗、扩展重载、快捷消除、代码小窗。

```
node tools/e2e-test.js <chrome.exe 路径> <空的临时目录>
```

浏览器放在临时目录、Windows 沙箱读不到可执行文件时，先设置环境变量 `E2E_NO_SANDBOX=1`。

## 说明

- 浏览器内置页面（`chrome://`）和扩展商店页面不允许任何扩展注入内容。
- 要作用于本地文件（`file://`），需要在扩展详情里打开「允许访问文件网址」。
- 规则保存在浏览器本地（`chrome.storage.local`），不会上传。换电脑或重装前请用「导出」备份。
